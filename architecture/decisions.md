# Architectural Decisions

What was decided and why. Newest first. `/save` appends here; `/resume` reads it.

## 2026-10-26 — MontageStudio is mirrored to a private GitHub repo by `git subtree split`; the vault stays the source of truth
`notnauti/montagestudio` (private) holds the project's own history: every vault commit that touched `03 Projects/MontageStudio/`, rewritten so each holds only that folder. The vault gets no new remote. To sync, re-run `git subtree split --prefix="03 Projects/MontageStudio" -b montagestudio-split` and push that branch to `main` by URL. Syncing is manual and deliberate, because `/save` never pushes. The project's own `.gitignore` now ignores `.env`, so a standalone clone can't commit a key; inside the vault the root `.gitignore` already covered it. `README.md` has no `(C)` prefix because GitHub only shows a README with that exact name. Private, because `logs/`, `CLAUDE.md` and the specs are vault notes full of wikilinks that are dead links outside the vault.

## 2026-10-26 — `montage view`: stdlib read-only page over scene_plan.json; frames from the renderer, cached by content; the only action is re-rendering the preview; scene_plan shape unchanged
The PRD's refine step (FR-5–FR-9): an agent edits over `montage mcp`, a person watches here. `view.py` is `http.server` (ThreadingHTTPServer) on 127.0.0.1, a free port unless `--port`; `view_page.py` is one self-contained HTML string (vanilla JS, no external requests, plan values through `textContent` only, since an agent writes the plan). **No endpoint writes the plan**; the only POST re-renders `cache/preview.mp4` through `render.preview` in a background thread. Approval stays a CLI act (`montage approve`), never a page button. Fixed routes only (`/`, `/api/state`, `/api/plan`, `/api/frame?n=`, `/preview.mp4` with byte ranges), so there is no path to serve arbitrary files; a request whose Host is not this server is refused (DNS rebinding), and so is a POST with another Origin; CSP `default-src 'self'` plus inline script/style and `blob:` images. **Frames** go through `frame_context.grab` (captions on, 640 px) on a plan normalized once per content key; the key hashes `review.fingerprint` (plan + every asset by sha256), so the cache under `cache/view/<key>/` follows content, not mtime, and a frame is pinned to the snapshot it was asked for (an edit landing mid-request cannot be cached under the old key). One ffmpeg job at a time (grabs and the preview share a lock); the page queues frame requests one by one. **State** is recomputed only when the plan's sha256 or the preview's mtime changes; the page polls `/api/state` every 1.5 s. Gates shown: script (none / untracked / draft / approved / changed via `script_gate.status`), storyboard (`approval.check` problems), preview (`review.stale_reasons`). `view` and `mcp` sessions are logged but not counted as work time (production.py `UNTIMED`). Live on a JWST scratchpad copy in Chrome: gates matched the real records, shot_06's frames and caption words were right, an edit to the plan redrew the page and turned both gates stale with the right reasons, and Re-render made the preview fresh again while the storyboard stayed unapproved. That check found a page bug the suite could not: every frame request was dropped because the queue ran before the image was attached; the page JS has no automated test.

## 2026-10-26 — Asset queries are suggested before scrape from the brief, not by the script writer; brief query > suggestion > description; scene_plan shape unchanged
The PRD's FR-2 had the script writer propose each asset's search `query`. That cannot work: sourcing runs before `plan` (decision 2026-10-02), so no script exists when scrape needs its queries. Instead `montage scrape --suggest-queries` (queries.py) asks Claude (one request, structured JSON with the wanted srcs as an enum, effort low, server-side fallback) for a 2-6 word archive-style query per wanted asset **without** a brief query, from the brief's premise and each description; the JWST hand queries are the style examples in the system prompt. Suggestions are saved to `cache/queries.json` (merged per asset, with model and time) and reused by every later scrape with no model call; `--suggest-queries` asks again. Precedence per asset: a `query` in brief.json (hand-written) > a saved suggestion > the description-derived search. brief.json is never written: it is the person's input. Opt-in and gated like `--vision`: exit 2 before any request without credentials; a failed request, or a suggestion breaking the rules (word count, missing or duplicate asset: rejected whole), leaves the description search and the run exits 2. `Wanted.query_from` (`brief` / `suggested` / `description`) is printed per asset and recorded as `queryFrom` in manifest entries and candidates.json (so `--pick` keeps it); production.py counts `handQueries` (entries with `queryFrom: brief`; older entries have none and are not counted), so the ledger shows whether suggestions remove hand work.

## 2026-10-26 — publish-pack: thumbnail candidates clear of every transition; `--draft` is opt-in Claude text; one Claude model constant; scene_plan shape unchanged
**Thumbnails (FR-10):** up to 3 frames, one per source file, the middle of each third of the eligible clips, each mid-way through the span where its clip is alone on screen and ≥6 frames clear of any cut or crossfade (the JWST pick fell inside a crossfade). Grabbed through `frame_context.grab` (the renderer's own chain), captions off, re-encoded to 1280 px JPEG at the best `-q:v` that fits 2 MB, into `publish/thumb_candidates/` (old `thumb_*.jpg` removed first) and listed in a `## Thumbnail` section. A failed grab is listed with its reason and warned on stderr, never a refusal or a non-zero exit: the pack is the deliverable, thumbnails are suggestions. Spread by time, not judged on looks (inferred trade: no vision call per pack); on JWST the three picks were clean but not the hand-chosen gold mirror. **The "already exists" check moved to the CLI, before any work**, so a refused overwrite neither replaces the candidates nor pays for a model call. **Drafts (FR-11):** `--draft` is **opt-in**, like `scrape --vision`, not automatic "when a model is available" as the PRD said: a key in the shell would otherwise make every pack, and any test calling `cli.main`, a billed call. Claude writes title (≤70), description intro (≤1500), exactly one title per chapter (given the narration of every beat the chapter merged), ≤15 tags; credits, NASA line and disclosure stay copied from the records. Any broken limit rejects the whole draft; the pack is then written with the brief's text and the command exits 2. No credentials: exit 2 before any request. **One model (FR-4):** `script.CLAUDE_MODEL = "claude-opus-5-5"`, imported by vision and drafts. The script writer moves from `claude-opus-5` (decision 2026-09-28) to it; never run live either way.

## 2026-10-26 — Production measurement: a per-workspace command log, a per-video summary, a versioned ledger in `logs/`; scene_plan shape unchanged
The cadence PRD's metrics (hands-on time, hand edits per video, YouTube signal) need numbers nobody kept. `cli.main` now wraps every command: one line in `<ws>/production_log.jsonl` (cmd, argv, start, seconds, exit, including `exception` / `interrupted`), written only into a directory that has `brief.json` or `scene_plan.json` (a bare `validate x.json` resolves to the cwd; two existing tests put a log in the project root before this rule), and a logging failure never fails the command. Hand edits are **derived from records the pipeline already keeps**, never logged separately: script changed after the model draft (script_approval.json hashes; `None` for a hand-written script), `pickedRank` entries, cache/plan-history/ snapshots, manifest entries without scrape's `ranking` field, and forced renders / `--rewrite` / approvals from the log. `publish-pack` (with `--hands-on-min`, asked on a TTY) and the new `montage stats` write `<ws>/publish/production_summary.json`; hands-on minutes, URL and YouTube day-7/28 stats carry over when the rest is re-derived. `mcp` and `stats` time is listed but kept out of the total (an open MCP session is not work). **Ledger location:** `logs/production-ledger.jsonl`, one JSON row per video upserted by workspace name: tool-emitted, so it belongs in the agent layer (AGENTS.md), and versioned because workspaces are not (2026-10-04). It is written only from a real command line, or a test that sets `MONTAGE_LEDGER`. `stats` never writes the publish pack, so a video made before logging (JWST, hand-merged youtube.md) can be backfilled; its summary says `logged: false`.

## 2026-10-04 — `montage preview` (480p animatic) is a second way to review; approval freshness by sha256 sidecar, not mtime; scene_plan shape unchanged
**Preview:** `montage preview <ws|plan> [-o out] [--no-captions] [--skip-normalize] [--skip-qc]` renders the plan as it is, approved or not (that is its job), to `<ws>/cache/preview.mp4`. It is the render's own graph (`render_command`, `write_subtitles`, normalize cache) at `profiles.preview_spec()`: 480 px short edge (854x480 for 16:9), the plan's own fps (frame-exact captions and cuts), libx264 `ultrafast` crf 30, AAC 128k, captions burned in, narration kept. Three differences from the delivery render, all for speed: one ffmpeg pass with single-pass (dynamic) `loudnorm` instead of measure + linear; no zoompan supersampling (1x, small jitter accepted); and each still is decoded and fitted once, then repeated with `loop` + `setpts=N/fps/TB`, instead of image2 `-loop 1` re-reading and re-decoding the file every frame (14.1 s vs 0.4 s for 300 frames of a 2220x1665 JPEG, extracted). QC is light: frame count, size, fps, codecs; no EBU R128 pass. Exit 0 ok, 1 invalid plan or non-.mp4 `-o`, 2 ffmpeg/tool failure, 3 light QC failed. Not a `--profile`: a preview is for review, never delivery. Live on a scratchpad copy of `jwst-unfold` (extracted): 81.6 s plan, 2449 frames, rendered in 14.3 s (54.2 s before the still change), QC 5/5, one-pass loudness came out at -14.1 LUFS / -1.4 dBTP. The still-once path is used **only** by the preview; moving it into the delivery render would cut its time too, but needs a frame-by-frame comparison against the current output first (inferred, not done).

**Freshness by content:** every contact sheet and preview now gets a sidecar `<artifact>.source.json` (`review.py`): kind, the artifact's sha256, and the sha256 of scene_plan.json and every asset, taken *before* drawing or rendering, so a plan edited mid-render leaves the artifact stale. `montage approve` accepts `contact_sheet.png` or `cache/preview.mp4` (default paths only; `-o` elsewhere gets a record but does not count) when its record matches the plan and assets now and the artifact's own hash still matches; otherwise it lists why for both and exits 1. approval.json records whichever was fresh under `contactSheet` and/or `preview` (`check()` and render are unchanged). This replaces the mtime test, which a copy, checkout or `touch` could fool both ways. **Behaviour change:** a sheet with no record (any sheet drawn before today, including `workspace/jwst-unfold/contact_sheet.png`) is not trusted; run `montage contact-sheet` or `montage preview` once before the next approve. The existing approval.json there stays valid until the plan or an asset changes.

## 2026-10-04 — Piper reads a speakable form, captions keep the written words; `publish-pack` writes the upload text from recorded provenance only; scene_plan shape unchanged
**Speakable text** (`speakable.py`): each narration line is rewritten per display token before TTS, deterministically: integers without "and" ("344" → "three hundred forty-four"), decimals digit by digit ("6.5" → "six point five"), 4-digit numbers 1100-2099 with no comma, sign or unit as years ("2021" → "twenty twenty-one", "1905" → "nineteen oh five"), decades, ordinals, leading −/- as "minus", ranges ("10-20" → "ten to twenty"), units after a number, attached or apart (%, °C/°F, m/km/µm, kg, s/ms/µs, km/s, Hz, AU, ...; singular only for exactly 1), currency ("$10 billion" → "ten billion dollars"), and a few abbreviations (Dr., e.g., i.e., etc., vs., &). Forms that read two ways stay as written and are left to espeak or the lexicon: "4K", "60s", "L2", "5G" (inferred trade: a wrong expansion is worse than espeak's default). An optional `<ws>/pronunciations.json` (`{"Webb": "web"}`, one-word keys, exact then case-insensitive, possessive `'s` kept) wins over every rule. **Captions:** each written token maps to the run of spoken tokens it became; Piper's spoken-word timings fold back into one span per written word (first start, last end), so captions.json and the caption track still show "2021." while the voice says "twenty twenty-one". If the counts ever disagree the line is spoken as written, so the mapping cannot drift. **Cache key:** the wav name hashes voice + *spoken* text, and the words file records `spoken` only when it differs. A line no rule touches hashes exactly as before, and old words files stay valid; on `workspace/jwst-unfold` only beat 1 ("2021.") gets a new wav, so its approval will need redoing after the next `plan` (extracted from a scratchpad copy). A bad pronunciations.json exits 1. **Pruning:** after the new scene_plan.json and captions.json are written, `plan` deletes narration files that no current beat uses, matching only montage's own names (`beat_NN_<10 hex>.wav`, `.words.json`, `.tmp`). A hand-placed wav in `assets/narration/` is never touched. The script gate still estimates runtime from the written words; spelled-out numbers make lines a little longer than that estimate (not changed).

**`montage publish-pack <ws> [--force]`** writes `<ws>/publish/youtube.md` and never `<ws>/youtube.md`. It never overwrites without `--force`. It uses only what the workspace already records: brief title and premise (verbatim), chapters from the narration clips' start frames in scene_plan.json (first at 0:00; beats merged until each chapter is at least 10 s; left out with a note if fewer than 3 remain; titles are each chapter's first clause, a draft), a credit block per used asset with `title`, `attribution`, `pageUrl`, `license` and `licenseUrl` copied exactly from manifest.json, the NASA no-endorsement line when a NASA item is used, draft tags (title, the words every asset description shares, recipe, then the brief's content words minus stopwords and words about the video itself), and a synthetic-voice disclosure that names the model only when `script_approval.json` records a model writer. **Refusals (exit 1, every reason listed):** the plan fails the same approval check `render` runs; there is no render, or the newest file in `renders/` is older than scene_plan.json; a used asset (montage's own narration wavs excepted) has no manifest entry, lacks source URL, author or license, carries a license scrape would refuse (re-parsed; `source-policy` only for `nasa`), is CC BY* with no license URL, or its sha256 differs from the manifest's (the credit would describe another file; inferred: not in the request, added because a hand-swapped asset otherwise keeps the old credit). A hand-supplied asset therefore needs a hand-written manifest entry before publishing. No upload API: the pack is text to paste.

## 2026-10-04 — Script gate before narration: a model draft waits for approval by sha256; hard limits reject it; speaking rate recalibrated to 3.1 words/s; scene_plan shape unchanged
`montage plan` now prints a beat table after the script exists and before Piper runs: beat, estimated seconds, words, asset, which brief points the beat says, and a narration excerpt; then words, speech + recipe pauses = estimated runtime against the target, and each brief point with the beat(s) that cover it or NOT COVERED. **Who stops:** a script a model wrote this run, or a model draft not yet approved, or an approved script that has since changed. The run exits 0 with a `next:` line and narrates nothing. `plan --approve-script` (approve and continue) or `montage approve-script <ws>` (approve only) writes `script_approval.json` (`draftSha256`, `writer`, `approvedSha256`, timestamps, optional note). The hash is over the script's content (title + beats, canonical JSON), so reformatting needs no re-approval but any changed word does; `--rewrite` starts a fresh record, and `--rewrite --approve-script` is refused (nobody has read the new draft). A script.json with **no record** (written by hand from scratch, or from before the gate, like `workspace/jwst-unfold`) is not held: its table is printed and planning continues, so the hand-written path and existing workspaces work as before. `--no-script-gate` skips the stop for automation. **Hard checks:** estimated runtime more than 15% over the target, or more beats than the recipe's maximum. They reject an unedited model draft (exit 1, reasons printed, script.json kept so it can be edited; approval and `--no-script-gate` cannot override them). Once a person edits the script they become warnings. Soft warnings: too few beats, more than 15% under target, uncovered or out-of-order points, a line longer than its video. **Coverage is deterministic, with no model call** (`coverage.py`): the brief is split into sentences; a colon ends the framing; the list after it is split at commas and semicolons; a fragment with fewer than two content words is merged into the one before it; "for <audience>" fragments are dropped. A point counts as covered when one beat (or two neighbouring beats) says enough of its content words, with title words excluded, plurals, -ed and -ing folded, and numbers allowed spelled out ("344" = "three hundred and forty four"). This is a lexical proxy (inferred): it can credit a beat that merely mentions the words, and it misses paraphrase. The point list is printed so a person can judge. **Speaking rate:** `WORDS_PER_SECOND` goes from 2.5 to 3.1. Measured on the JWST run, Piper lessac-medium spoke 222 words in 70.4 s of wav, 3.15 words/s, between 2.4 and 3.8 per line (extracted). At 2.5 every estimate ran about 25% long, and the hard check would have rejected drafts that were within limits. With 3.1 the gate estimated the JWST script at 83 s; the real plan is 81.0 s. The rate is a voice property, so it is one constant and not a recipe field. **Writer prompt:** it now lists the brief's points numbered, to be covered in order with none skipped. The word budget is the target minus the recipe's pauses, with an explicit ceiling at +15%; more beats than the maximum is stated as rejected; filler openers, recaps and generic sign-offs are banned. The beat-count note that used to sit in `run_plan` is now a gate warning. A reused script.json that is unreadable or invalid now exits 1 (invalid input) instead of 2.

## 2026-10-04 — Scrape ranking fixes, a candidates sheet with `--pick`, optional Claude vision; scene_plan shape unchanged
Fixes the four ranker bugs from the JWST run. **Queries:** an explicit `query` is sent whole (stopwords dropped, no cap); a description-derived query drops the words *every* asset in the brief shares (the topic: "james webb space telescope") before the 5-word cap, keeping them only if fewer than two own words remain. Topic words still weigh in local scoring. **Stems stay local:** search APIs receive words as written (`sources.words`); stems (`terms`) are only compared in-process, and the manifest's `matchedTerms` show the brief's spelling ("james", not "jame"). Stemmer: -ies → -y, -es dropped after s/x/z/ch/sh ("launches" → "launch"), -ss/-us/-is untouched. **Ties:** more matched *distinctive* terms (used by no other asset in the brief), then larger original (Commons width × height, else bytes), then source order. **Scene-type penalty** (cheap, transparent, printed): a candidate whose title names people / a room / an illustration that the asset's own wording (description, query, narration) does not is × 0.75; named only in its description × 0.9. It cannot see pixels — captions name engineers on plain hardware shots too — so it is a nudge, not the fix. **The fix is review:** `scrape` keeps the top 3 per asset as small previews (`cache/candidates/`, never full files; a dry run fetches previews only), writes `cache/candidates.json` (everything needed to download later without re-searching) and `cache/candidates.png`; `scrape <ws> --pick <asset>=<n>` downloads candidate n through the same fetch (size cap, conversion, decode check) into `cache/pick/`, replaces the asset only on success, and writes the same manifest entry plus `pickedRank`. The license is re-checked on the stored record (only `nasa` may carry `source-policy`), so a hand-edited candidates.json cannot bring in an unusable license. **`--vision`** (opt-in): Claude (`claude-opus-5-5`, structured JSON, effort low, server-side fallback) scores each asset's previews 0-10 against its description and re-orders the top 3 before download; refused with exit 2 when no credential source resolves, and its first runtime failure (e.g. zero credit balance) switches it off for the rest of the run, keeps lexical order, and makes the run exit 2. Commons previews come from `thumb.wikimedia.org` at 330 px; `upload.wikimedia.org` answered unscaled originals with HTTP 429 on 2026-10-04 (extracted from the live run).

## 2026-10-04 — Credentials come from the project `.env`, loaded by the CLI entry only
`montage` reads `.env` at the project root when it runs as a command (`main()` with no argv), with a stdlib parser and no `python-dotenv`. A variable already set in the shell wins. Library code and tests never load it: the suite calls `cli.main([...])` and must never see a real key or make a billed call, and a test that removes `ANTHROPIC_API_KEY` to exercise the Ollama fallback would otherwise have it put back.

## 2026-10-04 — Workspaces are local and unversioned
`workspace/` is gitignored: scraped media, narration, caches and renders are large and can be regenerated, and each workspace already carries its provenance in `manifest.json` (source, license, attribution, sha256) and `approval.json`. A video's brief and script live there too, so a published video's inputs are not in git. Copy whatever must survive into the project's numbered folders.

## 2026-10-02 — MCP server before the canvas: agents edit scene_plan.json through validated, atomic writes; stdlib JSON-RPC, not the `mcp` SDK; scene_plan shape unchanged
`montage mcp <ws>` serves the guide §5 tools over MCP stdio (newline-delimited JSON-RPC 2.0) against the workspace's scene_plan.json. There is no canvas or `project.ts` yet, so the contract file is what gets edited. Every edit is a pure function on the raw plan; the result goes through the same validator as `montage validate` (ffprobe included), and only a valid plan is written: temp file + `os.replace`, the previous version copied to `cache/plan-history/`, and a refusal if the file changed on disk while the edit was being checked. A rejected edit leaves the file byte-identical, and any asset copied for it is deleted. `dryRun` checks an edit without writing it. Semantics: split keeps everything else in place and continues the source (in-point advances; a zoom keeps its value at the cut); trimming the gapless video track is a *roll* edit (the neighbour absorbs the change, nothing downstream shifts), and audio/caption trims move the edge in place with collision checks. `timeline_apply_easing` is `scale` only: `position` / `opacity` stay out of the contract and are refused by name rather than widened, and intermediate keyframes are refused with "split first". `timeline_retime_captions` snaps word edges to speech onsets/offsets in a 10 ms RMS envelope (−40 dBFS) within the tolerance. `asset_replace_broll` takes local paths and file:// URIs only (remote URLs would bypass scrape's license gate). `inspect_frame_context` renders the frame through the renderer's own filter chains plus the caption ASS, and describes it from the plan; there is no OCR model. Edits invalidate the storyboard approval as designed: contact-sheet + approve before render. Stdlib over the official `mcp` SDK because the SDK brings pydantic, anyio, httpx and starlette into a stdlib + ffmpeg project for seven methods. `remove_silence` / `balance_audio_lufs` (named only in §2) are not built.

## 2026-10-02 — Asset sourcing is keyword search with licensed-only downloads; the storyboard gate pins plan + assets by hash; scene_plan shape unchanged
`montage scrape <ws>` fills the brief's *wanted* visuals (a `src` with no file yet; the extension picks image vs video and the file lands exactly there, so brief, script and plan never need rewriting) from Wikimedia Commons, NASA Image Library and Archive.org via stdlib urllib (timeout, descriptive User-Agent, streamed size cap). No CLIP: torch is out of scope, so ranking is a transparent lexical score (title hit 2, description/keyword hit 1, beat narration words at half weight), printed with every result. Only PD / CC0 / CC BY / CC BY-SA are downloaded: NC is refused because a published video may be monetised, ND because cropping and zooming are derivatives. NASA's API has no per-item license field, so NASA items are accepted on NASA's media guidelines as a *source policy* (marked `licenseBasis: source-policy` in `manifest.json`) and refused when their metadata credits a third party. Downloads must decode a frame, not just pass ffprobe. Sourcing runs before `plan` (the script writer picks from existing files) rather than after it as in the guide. The gate: `plan` ends by drawing `contact_sheet.png`; `montage approve --workspace` writes `approval.json` with sha256 of scene_plan.json and every asset it uses, and requires a sheet at least as new as them; `montage render` refuses an unapproved or since-changed plan with exit 1 unless `--force`. The gate lives in the CLI, not in `render()`, so library callers and tests render directly. Found on the live run and fixed in the renderer: a full-range JPEG still made the output `yuvj420p` (QC fail); every clip now goes through `scale=out_range=tv`.

## 2026-10-02 — Captions: word timestamps from Piper's own phoneme durations; scene_plan gains a `caption` track
Supersedes the 2026-09-28 "Piper emits no word timestamps" premise. piper-tts 1.8 exposes per-phoneme sample counts once the voice's `Ceil` (duration) tensor is a graph output. Piper does that with the `onnx` package; we make the same one-field protobuf edit in stdlib (`align.py`, in memory, the model on disk is untouched), so there is no new dependency and no aligner model. Phoneme runs between espeak's word spaces become words; when espeak merges or splits words ("on the", "38"), each token is phonemized alone and fuzzy-matched to the timed phonemes; failing that, the timing is spread by word length and marked `estimated`. Measured against ffmpeg `silencedetect` on 6 real lessac-medium utterances: mean 12 ms, median 6 ms, max 77 ms at 18 pause boundaries (under one 33 ms frame, typically). Contract change: one optional `type: "caption"` track, `style` `highlight` | `pop`, clips `{id, startFrame, durationFrames, words[{text, startFrame, endFrame}]}` in timeline frames; words ordered, non-overlapping and inside their clip. No `src`: the plan stays self-contained for the renderer. `captions.json` (ms into each wav plus timeline frames) is the Stage 1 sibling. The renderer writes ASS and burns it in with the `ass` filter, path escaped for the filtergraph; recipes pick the style (`captionStyle`, explainer/documentary highlight, promo pop); `render --no-captions` skips the burn-in.

## 2026-10-02 — Render profiles, normalization and pipeline recipes leave the scene_plan shape unchanged
No new scene_plan field. `meta.resolution` / `meta.fps` stay the authoring grid every frame number is written in; `montage render --profile` (1080p30-h264, 720p30-h264, 4k60-prores) maps that grid onto the output at render time — short edge fixed by the profile, long edge from the plan's aspect, boundaries `round(frame × out_fps / plan_fps)`, crossfades re-derived from the mapped boundaries — and QC checks the profile's size, fps, codec and pixel format. Without `--profile` the plan's own grid renders in H.264, which is the slice 1 output. Hardware H.264 (NVENC / QSV / AMF) only after `ffmpeg -encoders` lists it and a 1-frame test encode passes, else libx264 with the reason printed; default stays libx264. Normalization (48 kHz audio, constant frame rate, 8-bit 4:2:0 / 8-bit stills, square pixels) writes to `<workspace>/cache/normalized/` and the render reads those copies; aspect mismatch is reported only, because `fit` already decides crop vs pad. ## 2026-09-28 — Explainer timing puts each crossfade inside the next beat's lead-in
Beat = lead (12) + spoken + tail (9); the visual overlaps the next beat by the 12-frame crossfade, so transitions never cover speech and `next.start == prev.end − crossfade` holds by construction. Reused video advances through unseen footage, takes the source's tail when fresh frames run short, and restarts only once the source is used up. A line longer than its video is an error, not a freeze or loop.
